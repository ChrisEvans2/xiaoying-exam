# 独立代码审查与边界测试

日期：2026-10-31。审查角色：本次开发的 review subagent。

本记录依据 `01-requirements.md`、`02-solution.md`、`exam.md`；确定性适配器测试只证明程序约束，不证明 DeepSeek 决策质量、真实向量召回或 MinerU OCR 效果。

## 审查清单

| 边界 | 核验目标 |
| --- | --- |
| 语义分块 | 相邻句段向量相似度影响分块；结构、长度、原文定位及表格关系不丢失 |
| 文档替换 | 同一 `document_id` 对应新修订；旧快照、旧 chunk、旧引用可读取，构建失败不改变发布版本 |
| 检索与引用 | 强制知识库及快照隔离；搜索仅候选元数据；只有成功读取的原文可引用 |
| 一次补充 | 仅一个窗口；补充恢复不重置预算；放弃/期限到达明确结束；故障与资料不足不同 |
| 并发与恢复 | 领取任务互斥、失效租约禁止提交；checkpoint/业务恢复不重复动作或补充；发布比较基线 |
| HTTP 与事件 | 相同键相同请求返回原结果，冲突请求 409；SSE 严格递增并支持断点续读 |
| 不可信输入 | 上传内容不执行；路径不能任意读取；伪造证据、跨版本证据与不支持文件明确失败 |

## 样本与评测工具复核

`tests/fixtures/qa_cases.json` 已更新为 schema 2，状态名与 API 一致。QA16、QA17、QA18 包含唯一一次补充后的预期；QA20 的注入错误统一为 TIMEOUT。独立检查确认：20 个唯一用例仍全部标为 `not_run`，8 份原始文件哈希与 fixture 一致。

`scripts/demo_cases.py` 使用真实 PG/LangGraph 和明确标注的脚本决策，并断言各场景预期状态。`scripts/evaluate.py` 在真实模式下逐题运行，不把参考答案或预期助手历史注入模型；启动时核对原始文件哈希、BGE 修订与 MinerU 索引，并检查评测期间版本未变化。后者仅自动比较状态，语义判断保留人工审阅。默认 DeepSeek 模型标识已改为 `deepseek-v4-flash`，真实 API 往返仍需凭据验证。

已逐份检查 5 个 `examples/scripted/` 记录：正常、冲突补充、读取恢复、持续失败、500→600 替换的实际状态与预期一致；Trace 序号连续且存在终态事件，均标为 `scripted_fixture_not_model_evaluation`。这些记录没有改变 20 题的 `not_run` 状态。

## 方案外新增功能

- `/health`：诊断接口，已测试不泄露 API 密钥。
- 显式 `mock` 演示模式：离线程序链路验证入口，不计作 DeepSeek 效果验收。
- PDF `test_text` 适配器：仅允许显式 mock 模式使用；上述配置测试已验证真实模式拒绝该适配器。MinerU 仍为默认方案，离线解析不代表 MinerU 成功。
- CLI `export`：导出持久化 run 与 Trace 的便捷入口；导出明确标记 `offline_mock` 或 `live`。
- `/file`：配套原文下载/PDF 预览端点，以知识库、版本和修订 ID 查询已保存文件，不接受任意磁盘路径；已测试跨库及不存在修订不能下载。
- `scripts/demo_cases.py` / `scripts/evaluate.py`：方案验收工具，分别生成脚本夹具记录和待人工审阅的真实模型记录，不增加业务功能；已接收主代理通知并短审。

## 2026-11-01：思考模式与多轮协议复审

沿用原 review subagent，独立新增 `tests/test_thinking_review.py`：**34 项通过**。审查指出思考模式不能使用 `tool_choice=required`，必须保留各轮 `reasoning_content`；没有或多个工具调用的响应也不能整轮丢弃，所有调用 ID 都须得到结果。这些问题已修复。
