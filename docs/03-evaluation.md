## 验收覆盖与判定

- 明确答案：QA01、QA02、QA05—QA10、QA12—QA15；覆盖住宿、交通、餐补、预借款、凭证和行程变更中的金额、条件及材料要求。
- 文档冲突：QA16，同时核对 Markdown 的 D01 和 PDF 的 D02；需要查证并澄清，不能依据日期替模型决定优先级。
- 资料外问题：QA17；信息不足：QA18，正确行为包含说明缺口或追问。
- 相似问法：比较 QA01 与 QA03；上下文追问：QA04 与 QA11，分别验证“待遇相同”和“资格不同”。
- 工具失败：QA19、QA20，与 QA01 使用同一个问题，分别验证成功读取后的回答和无法核实的未完成状态。

按事实、引用支持关系、资料缺口和任务状态判定，允许合理改写。JSON 中的原文片段是评测依据，不能提供给受测模型。没有适用证据时允许空引用；伪造引用、无依据给出金额、将未完成标为成功均判失败。

## 故障条件与执行记录

QA19、QA20 的搜索只返回 D04 的 ID、标题、日期等元数据，不返回答案摘要；禁止从缓存或其他读取通道获得正文。测试适配器按 JSON 的 setup 规格注入错误，实际工具名可映射逻辑角色 read_document。

QA19 首次原文读取返回可重试的 TIMEOUT，后续读取恢复；需要观察到模型读取错误后主动选择下一步，并在读取成功后引用原文。工具内部自动重试不能替代模型决策证据。QA20 所有原文读取持续失败，工具调用总上限为 6 次，允许模型提前结束；达到上限则必须报告未完成及上限原因。上述故障适配器及执行入口已实现于 `scripts/evaluate.py`；尚未使用真实 DeepSeek 执行。QA20 的实际注入错误统一为 `TIMEOUT`，持续失败语义不变。

真实评估运行器会将输入、实际输出及持久化 Trace 写入 `examples/live/`，包含工具参数、返回摘要和简短动作依据；参考答案不会注入模型。现有 `examples/scripted/` 由脚本决策适配器执行后导出，并明确标注不属于模型效果证据。

## 2026-10-31 实现后的验证结果

### 样本与需求对齐

JSON 已升级为 schema 2。QA16、QA17、QA18 初次都要求 `awaiting_user`；补充后 QA16/QA17 预期 `insufficient`，QA18 在转正、预算审批、无未清借款条件明确后预期 `answered`。这只是评估预期变更，20 条的执行字段仍是 `not_run`。

运行器在开始时核对 8 份原始文档的 ID/SHA、BGE 修订及 MinerU 配置，逐题检查知识库发布版本；基线变化则终止。状态符合不等于答案正确，输出中事实/引用判断始终保留 `needs_human_review`。

### 工程测试

- `uv run pytest -q --junitxml=examples/test-results.xml`：**90 passed in 4.27s**，真实 PostgreSQL/pgvector 和 LangGraph checkpoint，决策及 embedding 使用测试替身。报告：[JUnit XML](../examples/test-results.xml)。
- Python `F/E9/B023` 检查通过；前端 TypeScript 检查与 Vite 生产构建通过。
- 浏览器实测：选库、提交问题、终态刷新、SSE Trace、引用原文面板；页面 mock 提示清晰。PDF 真实区域预览和 UI 并发自动化尚未实测。
- review 构建的边界用例、18 项修复和各文件测试数见 [独立 review](review-notes.md)。包括超一万字分块、非法文件、表格关系、竞态发布、累计预算、迟到线程、旧租约/checkpoint 拒写和 SSE 断点续读。
