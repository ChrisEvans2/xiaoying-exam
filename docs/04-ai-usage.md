## 2026-10-31：转换为混合格式知识库

### 考生要求与转换分配

考生指出资料不能全部为 Markdown，要求将部分文档转换为 Word、PDF、HTML 和纯 TXT，增加四类文件格式。

| 文档 ID | 转换后文件 | 格式 |
| --- | --- | --- |
| D02 | `data/policies/D02-finance-intake.pdf` | PDF |
| D04 | `data/policies/D04-accommodation.docx` | Word |
| D06 | `data/policies/D06-travel-advance.html` | HTML |
| D07 | `data/policies/D07-missing-receipts.txt` | 纯 TXT |

D01、D03、D05、D08 保持 Markdown。知识库仍为 8 份制度，每个 ID 只有一个正式文件。

### AI 执行步骤

1. 读取原始制度和合成记录，在临时目录保存转换前文本，用于转换后的逐条核对。
2. 使用 `python-docx` 将 D04 转为真正的 Word 文档，设置 A4 页面、中文字体、标题、可见元数据和编号条款。
3. 使用 `reportlab` 将 D02 转为 PDF，嵌入中文字体并保留可提取文本。D01 与 D02 的期限冲突因此分布在 Markdown 和 PDF 两种格式中。
4. 将 D06 转为 UTF-8 HTML，保留可见元数据及对应 `<meta>` 字段，以语义化有序列表呈现条款；样式写在文件内，不引用远程资源。
5. 将 D07 转为 UTF-8 纯文本，移除 Markdown 标记，保留标题、元数据、合成声明和全部条款。
6. 从四类新文件中重新提取文本，与转换前的标题、元数据和条款逐一比较；仅忽略排版空白，HTML 列表编号按结构单独核对。
7. 将 Word 和 PDF 渲染为页面图片进行排版检查。转换验证完成后移除同 ID 的旧 Markdown 文件，避免重复入库，并更新 `data/README.md`。

### 验证记录

- 四类文件已通过真实文件格式、6 项元数据和全部条款的一致性检查；HTML 的列表顺序和各条文本也已核对。
- PDF 为 1 页 A4，中文字体已嵌入，全部正文可提取；页面图片已检查，无缺字、重叠或裁切。
- Word 首次渲染出现中文缺字和默认标题横线。AI 移除了标题边框及主题字体覆盖，并为临时渲染环境指定中文字体路径；重新渲染为 1 页，全部条款可提取，页面图片检查通过。此修复没有修改业务条款或系统字体配置。
- 最终目录检查通过：4 份 Markdown、1 份 Word、1 份 PDF、1 份 HTML、1 份 TXT，共 8 个唯一 ID；目录中的 8 个文档链接均有效。
- 四份未转换的 Markdown 与转换前逐字一致；四份已转换的旧 Markdown 在内容验证通过后移除。临时生成脚本、原文快照和排版检查图片不进入知识库。

### 实际修改

1. **删减文字**：移除顶部“让每个答案都有出处”、常态“本地工作区”标记、空白页标语与说明、固定推荐问题、侧栏说明及重复版本提示；移除“原子发布”等实现说明。咨询空白页只保留一个提问提示，输入框保留标签和发送快捷键。mock 环境仍在顶部明确标记“离线演示”。

5. **颜色及文字标签**：绿色用于用户提问、问题理解及用户补充；橙色用于工具调用与返回；蓝色用于模型决策、等待补充及正常结果；红色用于工具异常和执行未完成；其他系统状态使用灰色。节点同时保留标题与图例，避免只靠颜色区分。四种彩色标签的文字与背景对比度实测均超过 5:1。
6. **保留数据边界**：用户提问来自实际 run，问题理解来自现有公开 `query.expanded` 字段，工具内容来自已保存的 Trace。没有把私有 `reasoning_content` 或完整模型上下文暴露到页面，也没有编造新的模型推理记录。切换 Trace 时补充旧 SSE 回调失效检查，避免上一条连接继续更新当前页面状态。
