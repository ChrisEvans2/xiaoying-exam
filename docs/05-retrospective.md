# 问题记录与学习：
1. 测试数据留进真实业务环境，后续在AI协作开发的时候，需要分开测试和真实业务环境。否则容易乌龙
2. 前端设计需要给出一些限制或者术语，都则AI会使用其默认的审美进行设计，并可能会引起交互不友好
3. 在开发过程中，要时刻，不断地补充或者考虑边界的问题，否则模型经过上下文的漂移导致他自己静默开发了开发者不想要的功能或者不知道兜底策略
4. 业务功能需要自己亲自检查，在开发过程中可以开一个独立的subagent作为review检查代码逻辑是否存在问题，以及构建测试用例。
5. 开发过程中需要保持AI“清醒”，用文档作为“外部知识库”来记录改动情况

# 最难的地方：
企业知识最难的地方在于知识库中文档格式的多样性，不同的文档可能需要不同的chunk划分，目前也只是有限地列出了5类，特别是PDF的内容，其蕴含的不只有二位的图片/表格/文本。
同时在开发过程中需要结合业务分析不断地更新/补充边界条件，让AI逐步深入了解获得更细致的需求定义。
