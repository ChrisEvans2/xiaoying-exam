# 企业知识问答 Agent：业务分析

本文依据 [考核要求](../exam.md) 和用户在聊天中确认的业务规则编写，作为后续实现与验收的需求基线；不代表功能已经实现。

## 1. 用户、目标与范围

用户是咨询企业制度或产品问题的员工。目标是提供有原文依据、适用条件清楚的答案；无法确定时，说明冲突或缺口，并在有限的补充信息与执行次数内结束处理。

- **当前知识范围**：多份短文档。现有材料为虚构公司的 8 份报销与差旅制度，包含 Markdown、Word、PDF、HTML 和 TXT，详见 [知识库说明](../data/README.md)。
- **后续知识范围**：支持单篇超过 1 万字的长文档构建知识库；长短文档遵循同一套证据、引用及冲突处理规则。长文档的处理方案与效果需后续实现、验证。
- **资料边界**：业务依据来自 `data/policies/` 中的制度正文。设计说明、参考答案和测试记录不作为问答证据。当前制度覆盖范围以原文为准，不把缺少某项规定解释为禁止该行为。
- **交付范围**：知识问答、上下文追问、补充信息、冲突与异常处理。不接入人工工单；界面、线上部署、多 Agent 和生产级 Runtime 不是本次考核必需项。

业务成功包括给出可靠答案，以及在充分说明缺口后按规则结束无法回答的问题。具体判定条件见第 6 节“成功标准”。

## 2. 输入与输出

输入包括当前问题、可选对话历史，以及一次补充机会中用户提供的必要信息。知识文档须保留文档 ID 与版本日期。

| 输出项 | 业务要求 |
| --- | --- |
| 回答 | 直接回应问题，说明适用条件；不能确定时说明原因 |
| 引用 | 给出文档 ID 与实际读取的原文片段，能够定位对应文档、版本及条款或位置 |
| 资料缺口 | 明确缺少的用户信息、制度依据或尚未消解的冲突；无缺口时为空 |
| 任务状态 | 使用“已回答”“待用户确认”“执行未完成”“资料不足”之一 |

没有可用原文时允许引用为空，不能伪造片段。输出应让用户看清当前结论、依据和是否需要补充信息。

## 3. 主流程与停止规则

理解问题及上下文 → 检索资料 → 读取相关原文 → 判断证据 → 回答、继续查证或请求补充。

| 当前发现 | 业务动作 |
| --- | --- |
| 证据足够且未发现冲突 | 给出答案与引用，结束为“已回答” |
| 检索结果不相关或覆盖不足 | 调整查询、补充检索，或读取更完整的相关原文 |
| 文档存在冲突 | 查证适用范围、优先级或替代关系；仍无法确定时列出冲突并请求确认 |
| 查证后仍缺少作答所需信息或资料 | 说明具体缺口，给用户一次补充、确认或放弃的机会 |
| 工具发生错误 | 在执行上限内尝试合理补救；无法完成必要查证时结束为“执行未完成” |

### 一轮补充信息

1. 同一个问题最多进行一轮补充信息，集中询问当前影响判断的必要信息，避免反复追问。
2. 发出补充请求后进入“待用户确认”，开始有限的等待期限，并让用户知道期限和可以放弃补充。
3. 用户补充后结合新增信息再次查证：证据足够则“已回答”；仍缺依据或冲突仍未解决则“资料不足”，不再发起第二轮补充。
4. 用户明确放弃补充，且现有证据仍不足以回答时，结束为“资料不足”。
5. 到期未收到补充，结束为“资料不足”，注明“等待补充信息超时”，不能声称用户已选择放弃。
6. 补充后的查证如果因工具错误、模型超时或执行上限而中断，则为“执行未完成”，不能把执行故障误报为资料缺失。

一轮补充信息限制的是向用户追问的次数，不限制为核实该问题进行的合理检索次数；检索等工具动作仍受统一执行上限约束。

## 4. 任务状态

| 状态 | 类型 | 判定条件 |
| --- | --- | --- |
| 已回答 | 结束状态 | 已提供足够证据支持的答案与引用 |
| 待用户确认 | 中间状态 | 已说明缺口或冲突，在期限内等待用户补充、确认或放弃 |
| 执行未完成 | 结束状态 | 工具错误、模型超时、执行步数或工具调用次数达到上限等原因，导致必要查证未完成 |
| 资料不足 | 结束状态 | 补充后仍无足够依据、冲突仍未解决，或放弃补充且无法作答，或等待补充信息超时 |

- 等待用户超时属于“资料不足”；模型或工具超时且未能恢复、完成查证属于“执行未完成”。
- 工具失败后如果恢复并取得足够证据，可以正常结束为“已回答”。
- 冲突未解决时，应说“无法确定适用规则”并保留冲突引用，不能笼统说“找不到资料”。
- 当前已配置：等待补充600秒、单次模型45秒、检索20秒、读取5秒、累计活跃180秒；模型12次、业务工具8次、执行节点40步。恢复不清零预算，具体方案及已执行检查见 [设计](02-solution.md) 和 [评估](03-evaluation.md)，不能采用无限等待或无限重试。

## 5. 证据与判断规则

1. **原文支持结论**：只引用实际读取的资料；引用必须支持对应结论及其适用条件，检索命中或标题相关本身不代表证据足够。
2. **冲突先查证**：文档版本日期较新不自动代表优先级更高，不能凭猜测、常识或保守倾向替制度决定优先级。
3. **允许依据已查到的资料作答**：只检索到 D01 且未发现冲突时，可以依据 D01 回答，不要求无限查找以证明全库不存在冲突。
4. **上下文用于理解**：“那试用期员工呢？”应承接前文主题，再核对适用规定。历史回答不能替代本次需要的文档证据。
5. **补充信息不等于制度原文**：用户补充可用于确认适用条件或提供查证线索；引用仍须指向实际读取的原文，不能把用户的说法包装成制度条款。
6. **动作随证据变化**：模型根据检索与读取结果决定补充检索、读取、追问或停止；固定条件分支、自动重试或预设日志不能替代模型决策。

例如，D01 规定报销期限为 30 天，D02 规定为 15 天，适用范围相同且未给优先级。系统应列出双方原文、继续查证并请求确认；补充后仍不能消解冲突，就以“资料不足”结束，不能自行选定 15 天或 30 天。

## 6. 成功标准

本节把已确认的业务规则转为可核验的判据；整体验收门槛是本次补充建议，供考生检视。定义标准不代表功能已经达标。

### 6.1 单次问题何时算处理成功

| 最终结果 | 是否算业务处理成功 | 必须满足的条件 |
| --- | --- | --- |
| 已回答 | 是，前提是答案通过核验 | 回答覆盖问题所需事实，适用条件正确，每项制度结论都有实际读取的原文支持 |
| 资料不足 | 是，前提是按规则结束 | 已进行必要查证并给过一次补充机会；补充后仍不足或仍冲突、用户放弃且无法作答、等待超时，均说明对应原因后停止；不得编造答案 |
| 待用户确认 | 尚未完成 | 已说明缺口和等待期限；需要继续观察补充、放弃或超时后的结果，不能仅凭发出追问就判定整个问题处理成功 |
| 执行未完成 | 否 | 如实报告故障、模型超时或执行上限，可以判定相应异常处理用例通过，但不能算业务问题已处理成功 |

### 6.2 可核验的通过条件

| 编号 | 检查项 | 通过条件与检查证据 |
| --- | --- | --- |
| SC01 | 答案正确、输出完整 | 实际输出包含回答、引用、资料缺口和任务状态；对照用例，必要事实全部满足、禁止结论均未出现。允许合理改写，不要求与参考答案逐字相同 |
| SC02 | 引用真实且支持结论 | 逐项核对制度结论与引用，引用能定位文档及版本，片段来自实际读取结果且支持适用条件。无可用证据时允许空引用，但不能给出无依据的确定结论 |
| SC03 | 缺口与冲突处理正确 | 实际输出与 Trace 显示已查证、说明缺口或冲突；冲突双方均有引用，不凭日期自行选择。补充后的答案或结束状态与获得的证据一致 |
| SC04 | 交互与执行有界 | 运行记录显示同一问题最多一轮补充；补充成功、仍不足、放弃和等待超时均有对应结果；模型或工具故障未恢复、达到执行上限时返回“执行未完成”。测试须记录使用的有限时长及次数配置，并核对实际行为 |
| SC05 | 理解与答案随输入、资料变化 | 同义问题在相同条件下结论一致；上下文追问使用正确的对象与条件；替换制度内容后重新检索，答案及相关动作随新证据变化，保留替换前后的对照记录 |
| SC06 | 模型确实根据观察决策 | 至少两条真实模型执行路径体现“模型选择动作 → 工具执行 → 观察结果 → 调整下一步或结束”；实际 Trace 能说明不同工具结果如何改变后续动作，固定分支、工具自动重试或预设日志不算该证据 |

单条用例的判定：适用的必需条件全部满足才算通过；任一条件不满足则失败；尚未运行或缺少判定证据则为“未验证”，不能计作通过。持续工具故障用例可以因正确返回“执行未完成”而通过，但应与正常问题的回答成功分开统计。

以下属于关键缺陷，不能用其他用例通过来抵消：无依据的确定答案、错误或伪造引用、擅自裁决已发现的制度冲突、将未完成标为已回答，以及无限等待或突破已配置的执行上限。
